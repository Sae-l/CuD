# Sicherheitsprobleme melden

Bitte veröffentliche keine Zugangsdaten, personenbezogenen Daten oder ausnutzbaren Schwachstellendetails in Issues, Pull Requests oder Screenshots.

Melde Sicherheitsprobleme privat über [Security → Advisories → Report a vulnerability](https://github.com/Sae-l/CuD/security/advisories/new). Private Vulnerability Reporting ist seit dem 22.10.2026 aktiviert. Beschreibe dort betroffene Version, Auswirkung und minimale Reproduktionsschritte. Verwende ausschließlich eigene Testdaten.

Sollte die Schaltfläche dennoch fehlen, eröffne höchstens ein [öffentliches Issue](https://github.com/Sae-l/CuD/issues/new) mit dem Titel „Vertraulichen Sicherheitskontakt benötigt“, ohne technische Details oder Anhänge, und warte auf einen privaten Kanal.

CuD ist ein Einzelpersonenprojekt ohne zugesagte Reaktionsfrist oder Wartung älterer Versionen. Gib den Release-Tag oder Commit an und prüfe, ob das Problem im aktuellen Stand noch besteht. Für gewöhnliche Bedienfehler nutze die [Fehlervorlage](https://github.com/Sae-l/CuD/issues/new/choose).

Die Lernseite verarbeitet Lernstände im eigenen Browser. Ein öffentliches Repository oder Pages-Deployment ist keine private Ablage; `.gitignore` entfernt keine bereits veröffentlichten Dateien. Die Veröffentlichungsrechte werden getrennt in [RECHTE.md](RECHTE.md) behandelt.
